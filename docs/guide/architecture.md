# 架构详解

## 总览

![系统架构](../viz/architecture.svg)

系统由**四个模块**组成，支撑**两条独立的路**。

```
① 感受模块 ──→ ② 问题制造模块 ──→ ③ 执行模块(AI4S)
 视觉/听觉/文本    日常→前问题→科学问题      (解题)
                  →基础领域→问题树→融合
                        ↑
                  ④ 想象模块 (组词→拆词→还原造句→成段→解释)
```

---

## 两条路

### 问题路 · Problem Path

**目的**：把"困惑"变成**精确可判的问题**。

```
输入: 外部信息(视觉/听觉/文本) │ 日常问题 │ 母题
  ↓
日常问题 → 前问题 → 科学问题 → 基础领域 → 问题树 → 领域融合
  ↓
出口: 可判问题清单(带判定路由) → AI4S 执行模块
```

**成功标准**：答案成立 / 可判。

### 想象路 · Imagination Path

**目的**：把"词"变成**被理解的概念/理论**。

```
输入: 词(任意词 / 词对)
  ↓
① 组词 → ② 拆词(深度 d) → ③ 还原造句 → ④ 成段 → ⑤ 解释
  ↓
出口: 被理解的概念 / 理论
```

**成功标准**：解释语法正确 + 逻辑通畅 + 有推理判断。

**核心原则**（不可动摇）：

> 每个词都有意义，只不过是我们缺少想象力，无法理解它。

## 四个模块

### ① 感受模块

| 输入 | 处理 | 工具 |
|---|---|---|
| 视觉 | 图像 → 结构特征（密度/对称/熵/边界）→ 日常问题 | `perception_module.py` |
| 网络文本 | 抓页 → 疑问句抽取 | `web_experience.py` |
| arXiv | 摘要 → 开放点信号（open/unresolved/challenging） | `arxiv_miner.py` |

### ② 问题制造模块

| 阶段 | 做什么 | 工具 |
|---|---|---|
| 日常 → 科学 | 疑问分类（机制/数量/存在/定义）+ 判定路由 | `question_refiner.py` |
| 反例驱动 | 完整反例集 → 结构拟合 → 诚实探针 → 开放问题 | `counterex_engine.py` |
| 问题树 | Spec → L0–L5 分层 + 谱系门 | `territory_engine.py` |
| 全领域 | 14 领域 × 14 进程并行 | `all_domains_engine.py` |
| 领域融合 | 操作子 × 结构；领域级 + **结构桥梁**判据 | `deep_fusion.py` `field_fusion.py` |
| 新颖性门 | 机器真判 → OEIS 实查 → 结构可推性 → 显著性证书 | `novelty_gate.py` |

### ③ 执行模块（AI4S）

- `ai4s_harness.py`：对问题清单**独立验证**，产出裁决（confirmed / rejected / open），回灌清单。
- 已跑通：跨进制规律 13 条 confirmed。

### ④ 想象模块

五步流程，见 [想象路手册](imagination-path.md)。

## 关键设计决策

### 1. 两条路为什么必须独立？

因为**产出物不同**：问题需要"解"，概念需要"解释"。
用"是否已研究"去评判一个概念（如"记忆调性"），等于要求一个比喻必须先被证明为真——
那是范畴错误。

### 2. 为什么"显著性 > 新颖性"？

实测：**任选参数**的序列同样"OEIS 未见 + 结构不可推"。
所以"过 OEIS 门"是廉价的。唯一拦得住噪声的是**显著性证书**：
候选必须附带"具名对象的不变量"，且该不变量在 ≥2 个任意选择扰动下**保持不变**。

### 3. 为什么问题树要分层（L0–L5）？

实测：在 5 个领域 26 个问题上，
**L0（计数）与 L2（渐近）100% 被机器解掉**，真开放的全部集中在 **L1/L3/L4/L5**。
所以"母问题被解决"不等于"问题域被穷尽"——**它把问题推深了一层**。

### 4. 领域融合为什么要"结构桥梁"？

首轮筛出 286 个"可算+保结构"的候选，但抽样发现大部分是**无理由的配对**
（如"数论的对象 × 音乐的方法"）。补上判据（对象携带的结构 ∩ 方法作用的结构 ≠ ∅）
后降到 **144 个**，砍掉的正是最荒谬的那些。
