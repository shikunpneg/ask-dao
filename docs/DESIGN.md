# DESIGN — 问题制造器内部设计说明

## 1. 目标与口径（重审后锁定）

- **目标产物 = 问题**：系统提出"真实问题"——说人话可懂、有判定路径、判得出真结果；"前所未有"是惊喜指标不是及格线。
- **第二步口径**：真伪判定为主（形式域证明/反例/构造=真伪；经验域概念裁决先行），可行性后置。
- **判定者/制度**：美学等域无单机终审；可靠性由判定器注册表+诚实标签承担，判官字段留审计。

## 2. 问题生命周期(状态机)

```
种子疑问(日常) ─正名/可说性─► 候选命题(母题×模板×参数) ─判定器─►
   真(构造/验证) │ 假(最小反例/结构反例) │ 悬置(开放, 命中著名问题→标名) │ 待实验/待评审
                        │
                        └─ 悬置→ 分支为子问题(精化/约束+/换对象类/换域)  ← 树生长
```

## 3. 出处链(provenance) 字段

每个 `ProblemRecord`:
- `id/domain/seed`：出身
- `motifs[]`：用了哪些母题（可视化逐个点亮）
- `template`：套了哪条组合模板（如 "T1 域×对象类×两项和"）
- `binds`：绑定参数（对象类/约束/扫描域…）
- `statement`：精确到可判的命题表述
- `judgement{method, range, fails_head, threshold, …}`：判定证据原样存档
- `status/honesty`：状态 + 诚实标签（已知-著名 / 惊喜候选-需查证 / 及格线产物）
- `tree{parent, edge}`：在问题树里的位置与生长操作名（"加约束:两数不同"/"换域:偶→奇"/…）

## 5. 可视化如何"解释生长"

- 左栏：母题库总览 + 本次实际被组合的母题（带使用次数）。
- 主区：疑问树根（日常疑问）→ 问题卡（徽章=状态）。
- 展开卡：**母题 chips → 模板 → 参数 → 判定记录(反例清单/阈值/证明) → 诚实标签**，以及"从 X 生长: <边名>"。
- 意图：让观者验证"这个问题不是 LLM 顺手写的，而是基元组合+程序判定的产物"。

## 6. 数据格式（json）

- `problems_<domain>.json` = ProblemSet: `{domain, roots[], problems[](含 provenance)}`
- `viz/data.js` = `window.DATA = {registry, motifs_math, roots, problems, aesthetics}`
- `registry.json` = `{math_core:[{name,type,note}], domains:{域:[{name,type,note}]}}`

## 7. 工程纪律

- 纯标准库（>=3.9），无运行时依赖；判定纯函数化便于测试不同规模。
- 诚实 > 好看：任何"已知"标注都要有据；任何"惊喜"都强制带"需查证"。
- 增长与判定分离：新母题/模板可加，但判定器必须先行，否则登记为"待实例化"。
