## 第 8 部分 Claude Code 接手轮（R22）：三项整改 + 一处纠错 + 一个可判雏形

### 8.1 纠错：S2 "表观有界" 结论作废
旧记录（R15）称 "p∈{3,5,7} 奇 q≤71 停时单调爬升，表观有界但未证"。复算发现两处方法学缺陷：
1. **运行最大值同义反复**：`max over q≤Q` 对 Q 单调递增是集合扩张的必然，不含任何信息；
2. **窗口过窄**：旧扫描仅到 Q=71（奇 q 只有 36 个）。

新工具 `tools/s2_bounded.py` 改用**滑窗统计量**（窗口内 max / 中位）、存活率与无截断计数：

| p | 窗口中位（q 中心 100→4900） | 存活率 | 幂指数 a | 裁决 |
|---|---|---|---|---|
| 3 | 289→321→367→430→587 | ≈1.000 | 0.179 | **无界（随 q 增长，≈q^0.18）** |
| 5 | 366→356→362→353→347 | 0.93 | −0.013 | 窗口内有界（持平） |
| 7 | 134→139→135→130→132 | 0.86 | −0.008 | 窗口内有界（持平） |

- p≥5 存活率 <1：部分轨道未在截断内到达 1，故其"有界"是**条件于到达 1**的，非全局证明。
- **后果**：S2 的 OEIS"双未见 ×7"建立在截断敏感的统计量上 → 候选应降级，不应继续作为 M4 的支撑。

### 8.2 整改 A2：真 F1 良构门槛
旧门槛 `len(statement) >= 20` 形同虚设。新 `tools/cross_md_v4.py::f1_check` 要求结构化三元：
**obj（明确对象）+ quant（参数量词域，须含区间/集合）+ crit（判定判据）**，且 obj 不得为占位符。
- 结果：454 条笛卡尔组合，**0 条过门** —— 自动短语矩阵 100% 是空壳（只有对象碎片，无量词域、无判据）。

### 8.5 B5：把"言不尽意"做成可判雏形
把哲学断言重写为**最小文法类分离问题**：给定"意义模式"（形式语言 L），判定其最小文法类；
若 L 需要 ≥ 上下文敏感文法，则"有限的'言'（表层语法）不能穷尽该'意'"。
判定器 `tools/p_A5_yanyi.py` = 正则泵引理穷举 + CFL 泵引理穷举（**机器验证**，非关键词）：

| 意义模式 | 判定 | 与预期 |
|---|---|---|
| a^n b^n（嵌套依赖） | ≥CFG 且非正则 | ✓ |
| a^n b^n c^n（双重嵌套） | ≥上下文敏感（非CFG，机器验证） | ✓ |
| a^n b^n c^n d^n（三重嵌套） | ≥上下文敏感（非CFG，机器验证） | ✓ |
| ww（跨序列复制/交叉依赖） | ≥上下文敏感（非CFG，机器验证） | ✓ |
| Dyck（一般嵌套） | ≥CFG 且非正则 | ✓ |

- 诚实标注：组件理论（Myhill-Nerode / 泵引理）**均为经典 N1**；本脚本贡献是把"言不尽意"从
  哲学断言变成**可判分离问题**并给出机器判定器，**不主张理论新意**。

## 第 9 部分 直面核心难题（R23）：为什么发现不了新问题

### 9.1 诊断：这台机器从未真正执行过新颖性检验
四个结构性缺陷，合成同一个后果：

| # | 缺陷 | 证据 |
|---|---|---|
| 1 | 裁判**无法输出 N3** | `novelty_judge.py` 全文件无任何路径返回 N3；N3 仅出现在文档字符串 |

### 9.2 重建：真实的参照系与新颖性门
- `tools/oeis_index.py` —— OEIS 倒排索引（393,600 序列 / 1,076,816 窗口 / 4.7s 建成）。
  旧反查每次线性扫 40 万条，批量不可用；新索引 O(词长)。自检正确（质数→A000040、斐波那契→A000045 等）。
- `tools/novelty_gate.py` —— 四道真门：
  **G1** 机器真判 → **G2 实查 OEIS**（带偏移对齐）→ **G3 结构可推性**
  （常数系数线性递推 ≤4 阶 / 低阶多项式 / 差分·部分和·二项变换后命中 OEIS / 平凡序列）
  → **G3.5 构造伪影检测**（单调 = "运行极值"伪影，S2 教训形式化）
  → **G3.6 显著性证书**（具名对象的不变量 + ≥2 个任意选择扰动下保持，含容忍度与相对离散度）
  → **G4 分级 N0/N1/N2/N3**（**N3 路径已证明可达**，不再是死门）。

## 第 10 部分 反例驱动与问题级门（R24–R25）：首次端到端打通

### 10.1 结构性诊断（R24）：机器此前只提它已会答的问题
四条**可验证**证据：
1. 零个引擎 import registry —— `motifs` 只是 `add()` 的事后贴标签参数，母题从未参与生成；
2. `add(id_, seed, motifs, template, binds, stmt, judgement, status, tag)` 32 处调用，
   **stmt 与 judgement 同时传入** ⇒ 生成器没有语法表达"我不知道"；
3. 代码分布：生成 1087 行 / 判定裁判 428 行 / `tools/` 过滤探针 **3757 行** ⇒ 生成仅占 21%；
4. `preproblems.py`（唯一把反例变问题的模块）**从未被调用** = 死代码。

⇒ **机器只提它自己已经会答的问题；能被生成它的机器立刻结算的问题，是计算，不是问题。**
⇒ R1–R23 的 79% 代码在过滤侧，因为过滤器产生干净单调可汇报的进展（路灯效应）。

### 10.2 A2 — 生成侧"我不知道"的语法
`model.UNRESOLVED = "开放(机器无法结算)"`。允许记录只带陈述、不带判定。

### 10.3 A — 反例驱动引擎 `counterex_engine.py`
算完整反例集 → 拟合结构 → **诚实延伸探针**（向扫描上界之外再扫）→ 产开放问题，只带反例证据、无判定。
- **自纠错（第 6 次）**：首版用 set 迭代 + `if x>=n: break`，因**集合无序**漏掉较小加数，
  假造出 16166 个"例外"；改排序遍历后与 `records_engine` 的 `fail_count` **完全吻合**（66 / 75）。

### 10.4 产出 13 个开放问题（13/13 status=开放）

奇合数+三角数(13) / 奇合数+半素数(12) / 半素数+平方数(6) / 回文数+平方数(3922)。

### 10.5 问题级门 `tools/problem_gate.py`（R25）
序列门看不见定性问题（全库 85 条"不可判"）。新门做三件机器真能做之事：
**D1 结构族分类** / **D2 机器前沿**（放宽周期拟合、**类库包含检查**、延伸扫描、放大重拟合）/ **D3 渐近信号**。
- **自纠错（第 7 次）**：首版 `if cname in (a,b): continue` 跳过猜想自身的两类，
  恰好漏掉"例外集 ⊆ 三角数"这种**就在猜想类里**的关键情形。修复后 质数+三角数 升为"候选刻画"。
- 机器自行给出 6 条候选刻画，例如 **例外集 ⊆ {三角数} ∪ {216}**（质数+三角数）。

### 10.6 LLM/文献裁决（`tools/llm_judgment.py`）—— 两处机器独立重发现
| 问题 | 裁决 | 文献与吻合点 |
|---|---|---|
| 质数+三角数 | **N0 重发现** | **Zhi-Wei Sun (2008)**：每 n≠216 = p+T_x。机器例外集 ⊆{三角数}∪{**216**}，**216 正是唯一例外** |
| 质数+平方数 | **N0 重发现** | **Hardy-Littlewood 猜想 H**：文献例外 "10, 34, 58, 85,…"，机器(仅偶数) **[10,34,58,64,130,…]** 吻合；机器额外含 64/196/324(皆平方数) = 猜想排除"非平方"的可检测痕迹 |
| 质数+半素数 | N0 已知 | **Chen 定理**(p+P₂) |
| 其余 5 条 | N1 已知(小例外) | 未单独检索 |
| 3 条(密度/回文数) | N2 **检索未见(非新)** | 检索空或仅相邻 |

裁决分布：**N0×5 / N1×5 / N2×3 / N3×0**。

### 10.7 总结论（第三次更新）
- **机器的问题是真的**：两个做了文献检索的假设**全部与文献精确吻合**，包括 216 与 HL 例外集的偶数列。
  机器不靠任何文献输入，独立造出了 2008 年 Sun 猜想与 Hardy-Littlewood 猜想 H 的例外集
  —— **对"反例驱动生成"的有力验证**。
- **但没有一条是新问题**：N0×5 + N1×5 + N2×3（检索未见 ≠ 新）。
- **N3 = 0，世界新问题 = 0** 不变。**理由第三次变化**：不再是"没有可判数据"或"过不了序列门"，
  而是 **机器造出的问题是真的、但多数已被前人问过**。
- ⇒ **瓶颈从"机器不会提问"移到"机器提问的领地太拥挤"**（加性数论是数学中最拥挤的领域之一）。
  下一步应把反例驱动搬到**参照系稀薄的领地**，而不是继续在该领域增加对象类。
